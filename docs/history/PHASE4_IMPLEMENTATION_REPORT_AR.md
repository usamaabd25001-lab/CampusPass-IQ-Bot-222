# تقرير تنفيذ المرحلة الرابعة — V6.8 User Experience

## الهدف
تبسيط رحلة الطالب بدون إضعاف الحماية التجارية والمالية التي بُنيت في V6.5 وV6.6 وV6.7.

## النتيجة
أصبحت رحلة المستخدم مبنية على أربعة مبادئ:
1. يتصفح قبل التسجيل الكامل.
2. لا يُنشأ طلب أو يُحجز مورد قبل موافقة نهائية صريحة.
3. استلام بيانات الخدمة مختلف عن نجاح التفعيل.
4. السجلات الطويلة قابلة للتصفح والبحث بأرقام عامة.

## الأعمال المنفذة

### التسجيل المرحلي
- `/start` يفتح المتجر بعد قبول الشروط بدون إجبار الطالب على تعبئة الملف الدراسي كاملاً.
- عند أول شراء يُطلب الاسم ورقم الهاتف فقط إذا لم يوجد ملف.
- تحفظ الحقول الأكاديمية كغير مكتملة ويظهر زر مستقل لإكمالها لاحقاً.
- إكمال الملف لأول مرة لا يستهلك حصة تعديل الملف.
- العروض التي تحتاج حقولاً خاصة ما زالت تجمعها حسب تعريف العرض.

### تأكيد الشراء
قبل إنشاء الطلب يعرض البوت:
- العرض والمنصة.
- السعر ورسوم الخدمة والإجمالي.
- الصلاحية.
- مهلة الدفع.
- وقت التسليم المتوقع.
- بيانات التفعيل بعد إخفائها.
- الشروط.

لا يستدعي النظام `OrderService.create` إلا بعد الضغط على «أوافق وأنشئ الطلب». الإلغاء قبل التأكيد لا يحجز مورداً ولا مبلغاً.

### فصل التسليم عن التفعيل
أضيف إلى الطلب:
- `delivery_acknowledged_at`: المستخدم أكد وصول البيانات.
- `activation_confirmed_at`: المستخدم جرّب الخدمة وأكد نجاح التفعيل.

لا يستطيع المستخدم تأكيد نجاح التفعيل قبل تأكيد الاستلام. الإكمال التلقائي بعد مهلة الاعتراض يبقى موجوداً لحماية التسوية، لكنه لا يدعي أن المستخدم أكد التفعيل يدوياً.

### صفحات وبحث
- الطلبات: صفحات + `/order ORDER-ID`.
- الاشتراكات: فلاتر وصفحات.
- التذاكر: صفحات + `/ticket TICKET-ID` + صفحات رسائل من الأحدث إلى الأقدم.
- النزاعات: صفحات + `/dispute DISPUTE-ID`.
- كل بحث يتحقق من ملكية المستخدم قبل العرض.

### عرض عربي مركزي
أنشئت `app/core/presentation.py` لتوحيد حالات:
- الطلبات.
- الاشتراكات.
- التذاكر.
- المنصات.
- الدفعات.
- النزاعات والاسترجاعات.
- أدوار المرسلين.

القيم الإنجليزية تبقى مستقرة في قاعدة البيانات، والواجهة فقط تعرض العربية.

### وقت التسليم المتوقع
أضيف وصف مركزي حسب نوع الخدمة:
- مخزون كود/حساب: عادة خلال دقائق بعد تأكيد الدفع.
- رمز بريد: بعد وصول الرمز عادة خلال دقائق.
- دعوة بريد جامعي: الهدف خلال ساعات.
- خدمة يدوية أو ملف: الهدف خلال 24 ساعة.

هذا وقت مستهدف وليس ضماناً مصرفياً أو تعاقدياً، وتبقى متابعة SLA الفعلية ضمن مرحلة التشغيل.

## التوافق
- Migration إضافي فقط ولا يحذف أعمدة أو جداول.
- بقيت كل خدمات النزاعات والاسترجاع والخصوصية والأدلة فعالة.
- أرقام Public ID القديمة ما زالت صالحة.
- أزرار `disputes:list` القديمة بقيت مدعومة مع تحويل المستخدم للصفحة الأولى.

## حدود المرحلة
- لم تُجر تجربة Telegram حية لأن التوكن غير متوفر.
- لم يُختبر التدفق على Neon وRedis حقيقيين؛ هذا ضمن Phase 6.
- لا تزال بعض لوحات الإدارة كبيرة وتحتاج فصل تشغيلي في Phase 5.
- وقت التسليم المعروض تقديري حتى تُبنى Metrics وSLA فعلية.
