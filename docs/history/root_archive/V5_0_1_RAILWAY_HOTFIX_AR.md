# تحديث CampusPass IQ v5.0.1 — إصلاح Railway الجذري

هذا Patch يوضع فوق نسخة **v5.0.0** الموجودة في GitHub. لا يحذف المستخدمين أو الطلبات أو المنصات، ولا يحتوي على Migration لقاعدة البيانات.

## المشاكل التي يصلحها

- فشل Railway عند فحص `/health` وظهور `service unavailable`.
- تأخر تشغيل خادم الصحة بسبب انتظار قاعدة البيانات أو Redis أو Telegram.
- اشتراط `PUBLIC_BASE_URL` لتشغيل التقارير رغم عدم وجود Public Networking.
- عدم وصول التقرير عندما لا توجد وصلة عامة.
- ظهور قيم حساسة ضمن تفاصيل خطأ إعدادات Pydantic.
- توقف التشغيل بسبب فشل مؤقت عند إعداد أوامر Telegram.

## السلوك بعد التحديث

- Railway يفحص `/health/live` بدل `/health`.
- خادم الصحة يبدأ قبل Migrations وRedis واتصال Telegram.
- التقارير تعمل بدون `PUBLIC_BASE_URL` وتُرسل كملفات HTML وCSV داخل البوت.
- إذا وفّر Railway المتغير `RAILWAY_PUBLIC_DOMAIN` يكتشفه البوت تلقائيًا ويضيف رابط التقرير.
- `PUBLIC_BASE_URL` يبقى مطلوبًا فقط عند تفعيل الدفع الإلكتروني الخارجي `FEATURE_MASTERCARD=true`.
- `REPORT_SECRET_KEY` اختياري؛ عند تركه فارغًا يُشتق مفتاح ثابت من `ENCRYPTION_KEY`.
- `API_ADMIN_TOKEN` اختياري؛ إذا كان فارغًا تبقى واجهات الإدارة عبر الويب مقفلة.
- خطأ المتغيرات يعرض اسم المتغير والمشكلة فقط، دون طباعة التوكن أو القيمة السرية.

## طريقة الرفع

1. خذ Backup من PostgreSQL احتياطًا.
2. فك ضغط ملف Patch على جهازك.
3. ارفع **المحتويات الموجودة داخل الملف** إلى جذر GitHub.
4. وافق على استبدال الملفات التي تحمل الأسماء نفسها.
5. لا ترفع ملف ZIP نفسه كملف وحيد داخل GitHub.
6. لا تغيّر القيم الحالية التالية:

```text
DATABASE_URL
ENCRYPTION_KEY
ADMIN_IDS
```

7. تأكد أن `ENCRYPTION_KEY` لا يقل عن 32 حرفًا.
8. اترك `PUBLIC_BASE_URL` غير موجود أو فارغًا؛ لا تحتاج إضافته لتشغيل التقارير.
9. اجعل `FEATURE_MASTERCARD=false` ما لم تكن بوابة البطاقة مجهزة بالكامل.
10. انتظر Railway إلى أن يصبح آخر Deployment بحالة Active.

## الفحص بعد النشر

أرسل داخل البوت:

```text
/cancel
/admin
```

ثم افتح **معلومات النظام**. يجب أن يظهر:

```text
5.0.1
```

وجرّب إنشاء تقرير. إذا لا يوجد Domain عام، يجب أن يصلك ملف HTML وملف CSV مباشرة داخل Telegram.

## تنبيه أمني

إذا ظهر `BOT_TOKEN` سابقًا في صورة أو Log، ألغِ التوكن القديم من BotFather وأنشئ توكنًا جديدًا، ثم حدّث `BOT_TOKEN` في Railway.
