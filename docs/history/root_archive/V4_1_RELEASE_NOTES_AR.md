# CampusPass IQ Enterprise 4.1.0 — Production Hardening

هذا الإصدار يبني فوق النسخة الكاملة `4.0.1` ويركز على الأمان، الاعتمادية، الدفع الإلكتروني، والخصوصية. الترقية غير مدمرة: الجداول القديمة لا تُحذف، ويضيف التشغيل الأول جداول V4.1 الجديدة تلقائيًا.

## الدفع الإلكتروني

- تسجيل جلسة Checkout كدفعة Pending قبل تحويل المستخدم إلى البوابة.
- التحقق من HMAC باستخدام `PAYMENT_WEBHOOK_SECRET` المستقل.
- حد أقصى لحجم Webhook لمنع الطلبات الضخمة.
- استخراج مرن لمرجع العملية ورقم الطلب والحالة والمبلغ والعملة.
- رفض اختلاف المبلغ أو العملة أو ربط المرجع بطلب آخر.
- جدول `cp_payment_webhook_events` لمنع تكرار معالجة نفس الحدث.
- تأكيد الدفع وتغيير الطلب إلى `paid` ثم تشغيل التجهيز بصورة مستقلة.
- استئناف التجهيز بأمان إذا انقطع التطبيق بعد حفظ الدفع.
- تحويل الحالات المتأخرة أو المتعارضة إلى مراجعة إدارية بدل التسليم الخاطئ.
- مسار رجوع آمن للعميل: `/payments/return/{order_public_id}`.

## الاعتمادية والتوسع

- استخدام Redis لتخزين FSM وRate Limit الموزع عند ضبط `REDIS_URL`.
- استمرار التشغيل بذاكرة محلية إذا تعذر Redis، مع تسجيل الخطأ.
- PostgreSQL Advisory Lock لكل دورة Scheduler لمنع تشغيل المهام مرتين بين النسخ.
- دعم Retry آمن للـWebhook وللتسليم عبر Idempotency الموجود.

## الأمان والخصوصية

- رفض التشغيل في Production بدون مفاتيح تشفير وتقارير وAPI Admin قوية وثابتة.
- رفض القيم النموذجية Placeholder وروابط HTTP في Production.
- فصل `/health/live` و`/health/ready` عن التفاصيل الحساسة.
- نقل التفاصيل إلى `/admin/health` المحمي بـBearer Token أو `X-Admin-Token`.
- روابط التقارير صارت محدودة الوصول وقابلة للإلغاء من طبقة الخدمة.
- تقصير العمر الافتراضي لرابط التقرير إلى يومين بدل 30 يومًا.
- إخفاء جزء من عناوين البريد داخل التقارير.
- إضافة Headers تمنع التخزين المؤقت وفتح التقرير داخل Frame.
- إضافة سكربت `python scripts/generate_secrets.py` لتوليد أسرار آمنة.

## تجربة المستخدم

- إضافة تقييم موثق من 1 إلى 5 بعد اكتمال الطلب.
- تعليق اختياري مع منع تقييم الطلب قبل اكتماله أو من مستخدم آخر.
- إمكانية إظهار زر التقييم من تفاصيل الطلب المكتمل.
