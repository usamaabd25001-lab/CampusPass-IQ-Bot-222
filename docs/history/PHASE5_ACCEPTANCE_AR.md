# معايير قبول المرحلة الخامسة

1. الإصدار هو `6.9.0-operations-reliability-phase5`.
2. آخر Migration بنفس الإصدار.
3. توجد جداول النشر والمهام والنسخ والأعطال وتدوير المفاتيح.
4. Production يرفض `RELEASE_ID=local`.
5. Staging يرفض Bot Token الإنتاج.
6. `combined`, `bot`, `worker` قيم تشغيل صالحة.
7. `/health/ready` يتحقق من مكونات الوضع المختار.
8. التقرير اليومي يستخدم `ScheduledRun` ولا يعتمد على ذاكرة العملية.
9. النسخ الاحتياطي لا يضع كلمة المرور في process arguments.
10. النسخة تُشفّر وتُرفع ثم تُنزّل ويُتحقق من SHA-256.
11. Migration الجديدة تستطيع طلب Backup قبل التنفيذ.
12. Restore يحتاج تأكيداً صريحاً وبصمة اختيارية.
13. المفتاح القديم يستطيع فك البيانات أثناء التدوير.
14. الدفعة المعاد تشفيرها تسجل إصدار المفتاح الجديد.
15. أعطال Scheduler والBackup تسجل برمز ثابت.
16. فحوص المراحل 1–4 تستمر بالنجاح.
17. الحزمة الخارجية تحتوي 8 ملفات فقط.
18. Docker يثبت PostgreSQL client ويشغل Verify Phase 5 والاختبارات.
19. كل مكوّن bot/worker يسجل حالة نشر مستقلة ضمن نفس RELEASE_ID.
20. Railway deployment ID وGit SHA يُلتقطان تلقائياً عند توفرهما.
21. نجحت 63 اختبارات حماية للمراحل 1–5.
